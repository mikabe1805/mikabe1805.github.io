A pen freeze, traced and removed

In TestFlight Build 30’s code, pausing for about two seconds and then writing again froze the pen for about a second and a half. Profiling traced it to one long task on the UI thread: the app handling the sync echo of its own save, which re-encoded the whole library each time. The length of the pause only decided whether the next stroke landed inside that task.

The main fix changed how that echo is merged: the catalog now compares page records by their metadata alone. After the fix, the hold sits at the harness’s timer floor.

about 1.5 ms median (the timer’s floor), worst 8.3 ms

Measured in a desktop test that runs the app’s real editor, SQLite repository and sync service against an in-memory Firestore that mimics iOS delivery. Not yet confirmed on the iPad. The pad is a browser replay of the measured timing. The code measured as Now is in TestFlight build 33.

One page on every device

Pages use a fixed 900 × 1200 coordinate system, so nothing reflows between devices. The iPad is for Apple Pencil writing, the phone for board photos, scans and markup, and the laptop for typed notes, equations and code.

Saves and sync

Each edit and its pending sync operation commit in one SQLite (Drift) transaction with a durable outbox. Cloud changes sync as append-only Firestore operations, and when two edits conflict, both are kept as alternate copies.

Erasing one stroke

In Build 30’s code, one erase on a 2,000-stroke test page re-recorded about 1,000 strokes. Ink now lives in stable groups of at most 32, so the same erase touches about 30.

Apple Pencil input

Apple Pencil reports extra touch samples between display frames. I patched Flutter’s iOS engine so those coalesced samples reach the app, then compiled and signed the custom engine in Codemagic CI. TestFlight build 28 (September 23, 2026) ran on it, and so does the latest, build 33 (October 14, 2026).

When my iPad was slow to respond after waking, the work on it in build 33 also added a wake section to the app’s own Reliability report, with times and counts only, so the next slow wake shows where the time went.

Engineering content

Logic gates and breadboard parts sit behind the ink as vector stickers, equations are built by tapping each side of a fraction, and code blocks behave like source. A built-in half-adder notebook shows them together.

Since TestFlight build 33 (October 14, 2026), a typed equation can become a graph: tap GRAPH, and a vector graph appears under it and follows the equation as you edit it, computed on the device with no account or network. A Components tray adds 21 circuit parts, from resistors and sources to transistors, an op-amp and a flip-flop, drawn in the pen’s weight; on grid paper each part snaps to the grid, so an ink wire drawn to a pin meets it. New papers: Axes, Semi-log and Polar.

New features without a migration

Graphs and gates drawn in the pen’s line fit inside the existing block format: a graph rides in the field the gate stickers already use, and the new gate look is one added field. A device still on an older build keeps a graph byte for byte and draws a new gate as the classic one instead of hiding it, so no schema, local database or sync-rules version had to change.

Lecturer mode

Built and in private testing. A lecturer shows a QR code, and each student gets a private, offline-capable copy of the lecture. Answers to in-page questions stay anonymous to the lecturer, and none are shown until at least five students have answered.

If an answer is inappropriate, the lecturer can hide it or remove that student from the current question; a 30-day block is offered only after an earlier removal. Invitations last 90 minutes, and the server stores only a keyed digest of each one. I deployed it as a restricted pilot on August 29, 2026, on 31 Cloud Functions protected by App Check.

My part

I set the product direction from my own lectures and decided what each device is for. I started lecturer mode on my own initiative, run the release chain through Codemagic, TestFlight and Firebase, and test each build on my own iPad, iPhone and laptop.

Each change has to pass tests I specify and a visual review, then waits for my own check on my devices.
